# 发布说明 v1.0.15

迁移功能的最后一环：**换机器后 origin 变了，怎么让旧库继续可见**。

## 问题

插件的作用域是：

```
scope = 'manual-test:' + sha256(发送者 + origin)
origin = platform_name:message_type:session_id
```

`origin` 里的 `platform_name` 由 AstrBot 的平台实例决定。重装、换机器、改平台名之后：
库还在，但按新 origin 算出来的 scope 是新的，**查询全部落空**——表现就是“记忆没了”。

## 解法：会话认领（不改数据库）

```text
/dlm 会话信息                                    # 旧机器上执行，记下 origin 那行
/dlm 会话认领 aiocqhttp:FriendMessage:123456     # 新机器上执行
/dlm 取消认领                                    # 回到本机 origin
```

认领只做一件事：在**入口**把该发送者的 origin 换成你指定的旧值，于是 scope 与旧库一致，
61 张表一行都不用改。

绑定写在 `<数据目录>\scope_overrides.json`（原子写入，重启后仍生效），内容形如：

```json
{"123456": "aiocqhttp:FriendMessage:123456"}
```

## 安全约束

| 约束 | 原因 |
|---|---|
| 只接受 `platform:FriendMessage:session`（私聊） | 防止误把群聊纳入，群聊本来就不采集 |
| 目标 origin 下**没有数据就拒绝写入** | 抄错一个字符就会把新消息写进空会话，先验证再绑定 |
| 只影响本机、只影响该发送者 | 不改变其他会话，不改变全局配置 |
| `/dlm 取消认领` 或删掉 json 即恢复 | 可逆 |

## 一个需要知道的行为

认领后，**新消息也会写进旧作用域**（保持时间线连续）。如果你想让新消息归新会话，就不要认领，
改用「导出 → 导入」到全新会话。

## 测试

新增 `test_plugin.ScopeClaim` 2 项：

1. 拒绝：缺段、群聊类型、无数据的目标 origin；无参数时显示当前状态；
2. 认领：旧 origin 下的数据立刻可见（`/dlm 会话信息` 显示原话 1 条）、**重启后仍生效**、
   `/dlm 取消认领` 后回到本机 origin 且显示“未认领”。

全量 **347/347**，CI 在 3.10 / 3.11 / 3.12 三版本通过。
