# 发布说明 v1.0.13

把一直悬空的历史导入接口接上：`history_import` 模块有实现、有测试，但没有 `/dlm` 命令，
用户实际上用不到。这版补上入口，为“把以前的记忆搬进来”做准备。

## 命令

```text
/dlm 导入历史                     # 显示 imports/ 目录位置与文件格式
/dlm 导入历史 chat.jsonl          # 导入（只认 imports/ 下的文件名）
```

用法：

1. 把 JSONL 放进 `<AstrBot根>\data\plugin_data\astrbot_plugin_digital_memory_store\imports\`；
2. 私聊发送 `/dlm 导入历史 <文件名>.jsonl`；
3. `/dlm 待审` 查看导入的待审原话，`/dlm 导入来源 <序号>` 看来源标签。

文件格式：UTF-8 JSONL，每行 `{"message_id","speaker":"user","content","recorded_at"}`，
`recorded_at` 需带时区、不能是未来，`content` ≤400 字，单文件 ≤10 MB / ≤1 万条。

## 安全约束（不是这版新加，是模块原本的校验）

| 约束 | 原因 |
|---|---|
| 文件名不能带路径、必须是 `.jsonl` | 只读 `imports/` 目录，避免任意路径读取 |
| 同会话已有实时采集时拒绝导入 | 防止“历史源”和“实时源”混在一起，破坏来源可核验性 |
| 重复 `message_id` 跳过 | 幂等，可重复执行 |
| 导入顺序必须晚于已有导入记录 | 保持时间线单调，避免历史错位 |
| 只写为待审、不自动成为事实 | 与产品原则一致：未确认就是未确认 |

导入是**单事务**：任一行不合法就整批回滚，不会留下半截数据。

## 测试

新增 `test_plugin.HistoryImportCommand` 两项：

1. 无参数时提示目录与格式；`../x.jsonl`、`sub/x.jsonl`、`x.txt` 一律拒绝；
2. 导入两条后出现在 `/dlm 待审`（标注“历史导入”），`/dlm 导入来源 1` 能查到文件名。

全量回归 **341/341**（新增 2 项），CI 在 3.10 / 3.11 / 3.12 三版本跑同一套。

## 已知限制

- 导入的是原话，不做去重以外的清洗；`content` 超过 400 字会被拒绝（不是截断）；
- 一个会话只能“纯导入”或“纯实时”，不能混用（模块原有设计）；
- 目前没有导出功能；迁移请直接拷贝 `data\plugin_data\...` 目录或用面板归档。
