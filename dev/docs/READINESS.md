## 5. 建议的下一步（按 ROI）

1. **先拿 L0（1 周）**：用现有 QQ 链路连续跑 3 天真实私聊，同时做一次实机重启与一次真实恢复演练。
   产出《L0 验收记录》；期间暴露的问题优先于任何新功能。
2. **补真实语料（并行）**：脱敏 200–500 条真实对话，按"无内容追问 / 有内容改写 / 负例"分层；
   这是纠错与阈值工作的前置，没它就无法判断 65% → 70% 的真实差距。
3. ~~交付最小闭环~~：✅ 已完成（预设 + 安装/升级/回退 + INSTALL + 死代码移除 + `0.16.0`）；
   剩"新人照文档 30 分钟装好"的实测与插件市场安装验证。

明确暂不做：群聊、多设备、自动事实确认、5,000 条以上专项优化（除非压测证明个人场景会触达）、
把 LLM 判定升为默认路径。

## 6. 口径与风险

- 本文件里的 **65% / 27/35 / 15/15 / 20/20 等数字都来自自造语料**，只能当回归标尺，不能当真实准确率。
- G3 窄路的闸门参数按自造集调出，存在过拟合；真实语料上可能显著下降。
- 真实 BGE 的阈值结论只基于 4 个上游案例 + 15 条场景，样本很小。
- 最大单点风险仍是：**没有真实语料就无法判断语义是否"基本可信"**；其次是单人节奏（路线图风险登记）。
