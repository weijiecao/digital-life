# 指标口径（METRICS）

> 规则：**先写口径，再写代码，最后看数字**。本文件定义"怎么算"，`STATUS.md` 记录"现在多少"。
> 任何面板上的分数都必须能追到本文件里的一个公式和一段可复跑脚本。
> 版本：v1（2026-11-03）。

---

## 0. 为什么单独一页

核查报告指出的根因不是"功能少"，而是**没有验收口径**：53 个版本在同一节点打转，
因为没人能回答"还差多远"。本页的作用是让这句话可以被机器回答。

三个纪律：

1. **数字只从脚本出**：`python scripts/report.py` 生成 `STATUS.md`。
2. **模拟环境数字必须标注"替身"**：受控编码器/假 AstrBot 上跑出来的比例，不能当准确率。
3. **分母写清楚**：召回率的分母是"应召回问题数"，不是"全部问题数"。

---

## 1. R@1（目标原话召回率）

| 项 | 内容 |
|---|---|
| 定义 | 在**应召回**的问题中，返回的上下文里包含标注目标原话的比例 |
| 公式 | `R@1 = 命中问题数 / 应召回问题数`（每问题只看 Top-1 轮注入内容） |
| 标注单位 | 一条真实会话轮次：`query` + `expected_original_text`（原话原文，不写摘要） |
| 采集脚本 | `dev/eval_baseline_retrieval.py`（4 个上游案例，`any_hit` 字段）；未来 `dev/evaluation/` 的 100 条评估集 |
| 阈值 | L1 ≥ 70%；M3 目标：较 baseline +15 个百分点 |
| 已知口径风险 | 原话可能出现在上下文的"联想"里而非直接召回；因此只统计**原话全文子串命中**，不做模糊匹配 |

当前状态：**M2 自造 120 条基线**——真实 BGE 默认门槛（0.60）下 R@1 **64/100**，
0.55 时 **71/100**；无模型 29/100。语料是自造样本（`docs/EVAL_SET.md`），
不等于真实聊天准确率；脱敏真实语料到位后另加 `real-chat` 分册。

## 2. 误注入率

| 项 | 内容 |
|---|---|
| 定义 | 在**无相关记忆**的问题中，注入了任意内容的轮次比例 |
| 公式 | `误注入率 = 负例中被注入的问题数 / 负例问题数`（负例 = 标注"应无任何内容"） |
| 采集脚本 | `eval_baseline_retrieval.py` 的 `false_positive`；`evaluation/run_scenarios.py` 的 `empty` 预期项 |
| 阈值 | L1 ≤ 5% |
| 注意 | "注入了内容"包括"未确认的联想"；对个人场景来说，一条错误联想比漏召回更伤信任 |

当前状态：受控替身上负例 0/2 被误注入；M2 自造语料 20 条负例在真实 BGE 与无模型下**均为 0/20 误注入**；
**真实对话未测**。

---

## 3. 纠错正确率（改期/取消场景）

| 项 | 内容 |
|---|---|
| 定义 | 明确改期/取消场景中，同时给出**新旧两条原话**且标注"未确认"的比例 |
| 公式 | `同时含新旧原话且带未确认标记的样本数 / 纠错类样本数` |
| 判定要素 | ① 旧原话全文出现；② 新原话全文出现；③ 关系或说明里出现"未确认/可能/尚未确认" |
| 采集脚本 | `evaluation/run_scenarios.py` 的 `relation=True` 项（检查 `类型=修正`）；`eval_baseline_retrieval.py` 的 `unconfirmed_mark` |
| 阈值 | L1 ≥ 60% |
| 边界 | 只测"是否并列呈现"，不测"是否判断对新旧哪个是当前事实"——后者本工程明确不做（Non-goals 2） |

当前状态：M2 自造语料 35 条纠错样本，真实 BGE 下仅 3/35 同时给出新旧并标未确认；无模型 2/35。
主因是变化词表覆盖不足与 180 秒窗口，详见 `docs/EVAL_SET.md` 的 F-C。

## 4. P95 钩子耗时

| 项 | 内容 |
|---|---|
| 定义 | 从 `on_llm_request` 钩子被调用，到记忆片段写入 `extra_user_content_parts` 完成的耗时 P95 |
| 公式 | 所有轮次耗时升序后取 95 分位（nearest-rank，样本 < 20 时取最大值） |
| 采集脚本 | `integration_probe.py` → `reports/integration_chain.json` 的 `latency_ms` |
| 阈值 | L0 < 1.5 s；L1 < 2 s（两者都**不含**回复模型耗时） |
| 不含 | 模型回复、网络、AstrBot 自身排队 |
| 已知风险 | 首次加载 BGE 明显超过 1.5 s；单线程池被长任务占用会把 P95 拉高（P2-5） |

当前状态：替身上 P95 见 `STATUS.md`，但**不含真实 BGE 编码**，不能作为达标证据。

## 5. 自动覆盖率

| 项 | 内容 |
|---|---|
| 定义 | 用户不需要输入 `/dlm` 命令，也能产生记忆注入的轮次比例 |
| 公式 | `有注入且无命令的轮次 / 全部普通文本轮次` |
| 采集方式 | 探针里统计"连续 8 轮普通消息"的注入率；实机上按天统计 |
| 阈值 | L0 ≥ 80%；L1 ≥ 90% |
| 与"注入生效"的区别 | 自动覆盖率把"采集→整理→召回"全链路的静默失败都算进去；只看注入会高估 |

## 6. 辅助指标（L0 专用）

| 指标 | 定义 | 采集 | 阈值 |
|---|---|---|---|
| 采集成功率 | 授权私聊纯文本消息中，成功落库（`dl_capture` 有行）的比例 | 探针 `capture.rows`；实机按天对比平台侧消息数 | ≥ 99% |
| 缺口可见性 | 未采集的原因是否有记录（`dl_capture_gaps` 或日志） | `test_auto_jobs` + 探针 `gap_records` | 非文本链当前**静默跳过**（已知缺陷，见 STATUS 备注） |
| 备份可用性 | 备份可生成、可校验、可恢复到新目录、可删除 | `test_backup_regression` 4 项 | 全部通过 |
| 重启续跑 | 重启后积压任务自动处理，且不重复采集/重复注入 | `test_integration_chain` + `test_auto_jobs` | 通过 |

## 7. 证据分级（写进报告时必须标注）

| 级别 | 含义 | 可用于 |
|---|---|---|
| `real-qq` | 真实 AstrBot + NapCat + QQ 实聊 + 真实 BGE + 真实模型服务 | L0/L1 达标判定 |
| `real` | 真实 AstrBot + 真实 BGE（平台/模型服务可能是替身或 mock） | 框架层结论；**不等于 L0/L1 达标** |
| `fixture` | 受控编码器 / 假 AstrBot / 固定夹具 | 只能证明"链路通、契约自洽" |
| `none` | 没有数据 | 一律写"未测" |

`STATUS.md` 里所有 `fixture` 数字都已标注边界；`none` 的地方保留"未测"而不是填 0。

> 当前 `real` 证据：`docs/REAL_ENV_REPORT.md` 与 `reports/real_env.json`
> （AstrBot 4.29.3 + 真实 BGE，WebChat 平台 + 本地 mock provider）。QQ/NapCat 实聊与真实模型服务仍未验证。
