# M2 评估集与基线（v1）

- 日期：2026-11-04
- 语料：`dev/evaluation/m2_corpus.py`（**自造、分层、版本化**，非真实聊天记录）
- 运行器：`dev/evaluation/m2_runner.py`
- 基线数据：`dev/reports/m2_baseline_no_model.json`、`m2_baseline_real_bge.json`

> 路线图 W5–W7 允许"脱敏或自造"样本。本语料按真实对话形态手写，用于**回归与阈值扫描**；
> 它的分数不能当作"真实聊天准确率"。真实语料到位后应追加为 `real-*` 分层，而不是替换本集。

## 1. 语料构成（120 条）

| 类别 | 条数 | 形态 | 预期 |
|---|---|---|---|
| `named_event` 明确事件 | 20 | 1 条原话 + 提到事件名的问法 | 召回该原话 |
| `reschedule` 改期改口 | 20 | 原话 + 2 分钟后改期 | 新旧两条都出现且标未确认 |
| `cancel` 取消否定 | 15 | 原话 + 2 分钟后取消 | 新旧两条 + 未确认 |
| `similar_event` 相似事件 | 15 | 主事件 + 相似干扰事件 | 只召回主事件，禁止串味 |
| `cross_day` 跨日补充 | 15 | 1 号原话 + 3 号无关补充 | 召回 1 号原话 |
| `anaphora` 指代追问 | 15 | 原话 → 有内容追问 → “后来呢？” | 第二轮接住前一轮原话 |
| `negative` 负例 | 20 | 无关/近似但无相关记忆的问题 | **不注入任何内容** |

每条用例独立作用域（`scope = f(m2-user, case_id)`），走**自动路径**：
`capture → process_jobs → (真实 BGE 时) sync_text_index / sync_auto_source_vectors / sync_auto_topics → context_packet`。

## 3. 失败模式（按影响排序）

### F-A. 明确事件问法（10/20，改善但仍差）

`书店的事安排得怎么样？` 与 `原计划周六去书店找编程资料` 只共享 2 字“书店”，
而待审线索的门槛是**四字片段命中**。阈值降到 0.60 后语义路径把它拉到 10/20，
但短实体查询仍是最弱的一环；真实用户最自然的问法仍需要窄路或字面扩展。

### F-B. 指代追问 0/15（两档都是 0）

`context_turn` 的焦点（focus）只由“精确命名唯一事件”产生；自动路径的待审线索**不产生 focus**，
因此第二轮“后来呢？”没有可承接的对象，直接返回空。G3 窄路可解（自造 15/15），但默认关闭。

### F-C. 纠错成组：4/35 → 27/35（77%）

原实现只把**以变化词开头**的相邻短句并进“后续可能更新”，所以“搬家改到滨江区”“练车挪到周一早上”
（主题前缀 + 变化词）漏链；同时语义来源路径选到旧原话后不会带出新说法。
现在两处都补上：

1. `_possible_update_peer()`：语义来源选中一条原话后，若 180 秒内下一条是含变化词的短句，就一起给出；
2. `_pending_context` 的链式匹配从“必须整句以变化词开头”放宽为“短句内出现变化词”。

包内始终保留“未确认/新旧关系不确定”，不把两条合并成事实。剩余 8 条失败主要是：
变化句与旧原话间隔超 180 秒、或中间插入了无关消息（不符合“相邻”定义）。

### F-D. 负例 0/20 误注入，但串味 3 条

阈值下调没有造成负例误注入，但“相似事件”类别有 3 条把干扰事件也带进来了。
说明 0.60 的代价在**精度边缘**，需要在真实语料上复核后再决定是否降到 0.55。

## 4. 与 L1 目标的关系

- 65% 距离 L1 的 70% 还差 **5 个百分点**，且缺口集中在 F-A（明确事件 10/20）与 F-B（指代追问 0/15）；
  纠错已过 60% 线（27/35），串味是当前主要代价（3 条）。
- 该分数是**自造语料**，不能与真实用户对话直接比较；但作为回归标尺已经可用：
  任何改动都必须同时报告 R@1、误注入、纠错、延迟四项，禁止只看 R@1。

## 6. 维护规则

1. **语料版本化**：新增/修改用例必须改 `suite` 版本（当前 `m2-stratified-v1`），旧分数不可直接比较。
2. **禁止对着语料调参**：任何阈值调整必须在语料与真实样本上分别报告，并记录在 `BGE_CALIBRATION.md`。
3. **真实样本另加分册**：脱敏真实对话到位后追加 `real-chat` 分层，不改动现有 120 条。
4. 语料本身也有偏差（模板化、主题集中），在报告里必须标注 `authored`。

## 7. 每轮供给模式（always_context_enabled，v1.0.1 默认）

| 指标 | 命中口径（off） | 每轮供给（on） |
|---|---|---|
| 有上下文的轮次 | 66/120 | **105/120** |
| R@1 | 65/100 | 84/100 |
| 负例非背景误注入 | 0/20 | **0/20** |
| 背景-only 轮次 | 0/120 | 39/120 |
| 串味（禁注命中） | 3 | 11 |

> 供给模式把“无匹配时给背景”计入 R@1，因此数字更高；代价是串味从 3 升到 11。
> 背景包有独立标记（`背景上下文`），不会冒充相关证据；两种口径必须分开报告。
