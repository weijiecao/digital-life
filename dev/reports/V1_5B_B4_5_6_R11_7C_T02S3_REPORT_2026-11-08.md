# V1.5-B R11-7C：T02-S3 误合并归因报告

- 报告编号：DL-V1.5-B-REP-019
- 日期：2026-11-08
- 样本：同故事不同事件序列 T02-S3
- 状态：**归因为混合事件/更新语义与 Gold 口径问题；无算法修复**

## 1. 原始判决

输入：

```text
source:   同一个故事：主角在青岛开了书店，后来搬走。
candidate:同一个故事：主角在青岛开了书店。
story_id: story-2
```

模型输出：

```json
{
  "candidate_event_id": "series-event-07",
  "label": "SAME_EVENT",
  "reason_codes": ["same_story_id", "same_story_character",
                   "same_bookstore_plan", "later_relocation_is_continuation"]
}
```

## 2. 判读

T02-S3 不是“两个不同事件”的干净样本：

- source 同时包含 **同一书店事件** 和 **后续搬走**；
- candidate 是书店事件的前一状态；
- 模型把“后来搬走”解释为同一事件的更新，因而返回 SAME；
- 当前关系标签只有 SAME / RELATED / DIFFERENT / UNCERTAIN，**没有 UPDATE_OF**；
- 把 T02-S3 期望成 RELATED_CONTEXT 本身可能过严。

## 3. 干净负例对照

去掉同一事件提及，只保留不同情节：

```text
source:   同一个故事：主角后来去了成都。
candidate:同一个故事：主角在青岛开了书店。
```

模型输出：

```json
{"label":"RELATED_CONTEXT",
 "reason_codes":["same_story","different_location","different_action"]}
```

判读：

- 干净的不同情节下，模型正确返回 RELATED_CONTEXT；
- 说明当前 RelationJudge 能区分故事内不同事件；
- T02-S3 的问题主要是**一条消息混合了同一事件 + 更新**，不是关系模型完全失效。

## 4. 结论

- 不需要引入 StoryAnchor；
- 不需要扩展 V2；
- 不建议仅为 T02-S3 增加 UPDATE_OF 结构；
- 当前最小修复应是 **Gold/夹具修正**：
  - 将 T02-S3 标为“同故事、同事件 + 更新”或从“不同事件”集合移出；
  - 保留干净负例“后来去了成都”作为真正 different-event 测试。
- 若未来要区分“同一事件的更新”和“同一事件本身”，再考虑 `UPDATE_OF` 或事件修订；当前证据不足。
