- 状态：**完成；610/560/500 三个分母已解释**

## 1. 结论

上轮报告同时出现：

- 610 个金标准 pair；
- 560 个预测标签 / 560 个混淆矩阵条目。

差额 **50** 来自 **跨 scope pair**。  
另外还有 **60 个 `UNRESOLVED` pair** 进入 B2 评测，但不进入 pairwise 评分。

统一口径：

| 口径 | 数量 | 含义 |
|---|---:|---|
| 原始 pair | **610** | `pair_gold.jsonl` 全部 |
| B2 可评测 | **560** | 同 scope 且右侧有候选事件；50 个跨 scope 被 B2 scope 严格隔离 |
| pairwise 可评分 | **500** | 去除 60 个 `UNRESOLVED`（无 gold_event） |
| 跨 scope 排除 | **50** | B2 不做跨 scope 关系判断 |
| 未决排除 pairwise | **60** | `UNRESOLVED`，不能进入同事件/不同事件混淆矩阵 |

## 2. 逐项去向

| 状态 | 数量 | 说明 |
|---|---:|---|
| `pairwise_scored` | 500 | 200 SAME / 150 RELATED / 150 DIFFERENT |
| `excluded_cross_scope` | 50 | left/right scope 不同；B2 不判断 |
| `excluded_unresolved` | 60 | 没有 gold_event；不进入 pairwise |

## 3. 指标解释

上轮 B2 报告：

- Precision **0.9662**
- Recall **1.0000**
- F1 **0.9828**

这些数字的分母是 **560**，不是 610；其中包含 60 个 `UNRESOLVED` 作为负类。  
**500 个 pairwise 评分样本的指标尚未单独重算**；不能把 560 的 F1 直接写成 610 全量性能。

这不是程序错误，而是报告口径没有写清：

1. `v1_5b_b4_pair.py` 跳过跨 scope pair；
2. `UNRESOLVED` 被 B2 当作负类；
3. pairwise evaluator 只读有 gold_event 的 pair。

## 4. 修复动作

- 新增 `v1_5b_b4_pair_audit.py`；
- 输出 `v1_5b_b4_pair_audit.json`；
- 后续所有报告必须同时写 `raw / b2_evaluated / pairwise_scored` 三个分母；
- B2 报告注明 “560 含 60 unresolved”；
- 不重跑 LLM 也能解释差异；若需 500 pairwise 指标，需保存逐 pair 预测后重算。

**610/560 差异已解释：50 个跨 scope pair。**  
**另有 60 个 UNRESOLVED 不进入 pairwise，因此 pairwise 可评分为 500。**

在写明分母前，不能再用 0.9828 F1 推断 610 全量性能。
