# V1.5-B B4.5-6 R11 复杂叙事探测报告

- 报告编号：DL-V1.5-B-REP-018
- 日期：2026-11-08
- 数据：30 条人工构造 R11 A–F 合成案例（real_chat_records=0）
- 状态：**21 例修正序列 story 17/17、raw event 19/21、污染 0、Guard 误拒 0；无架构结论**

## 1. 方法

每条 case 提供：

- 一段叙事文本（故事/第一人称虚构/转述/嵌套/纠错/故事片段）；
- 一个候选事件，代表**用户真实经历**；
- 期望：`NOT_SAME_EVENT`。

使用当前 `RelationJudge`，只给一个用户事件候选，统计是否判成 `SAME_EVENT`。

## 3. 失败案例

- R11-008：第一人称虚构“我三年前在苏州工作”被判成用户真实事件；
- R11-010：剧本第一人称“我在成都开了一家公司”被判成用户真实事件；
- R11-026/028/029/030：故事内部片段被直接关联到用户事件。

这类错误不是“故事类型没识别”，而是：

- 第一人称代词“我”被当成用户本人；
- 故事内部事件与用户真实事件没有 provenance 边界；
- 当前 `RelationJudge` 只有事件关系标签，没有 `narrator / subject / reality_status`。

## 4. 判读

- R11 不能因 A/C/D/E 为 0 就通过；
- 第一人称虚构和故事内部片段是明确失败；
- 现有 50 对 narrative vs 非 narrative 探测过于宽松，不能代表复杂叙事；
- 不应直接改 Claim/双时态/图谱；应先设计 narrative provenance 字段或叙事专用判别。

## 4.1 ProvenanceGuard 结果

新增 `NarrativeProvenance` 与 `ProvenanceGuard` 后，对同一 30 例重新运行：

| 指标 | 值 |
|---|---:|
| 模型原判 SAME | 6 |
| Guard REJECT | 28 |
| Guard ALLOW | 2 |
| 有效误归因 | **0** |

Guard 阻止了 6 个 SAME 中的全部朝向用户真实事件；但 **28/30 被 REJECT**，说明当前规则可能过度保守。

**尚未验证故事内部连续性（同一 story_id 的片段能否被关联）**；因此只能说不把故事误归因为用户经历，不能说叙事记忆已完整保留。

## 4.2 故事连续性正例

新增 6 条 continuity case：

| 类别 | 通过 | 结果 |
|---|---:|---|
| 同故事不同片段 | **0/2** | 模型均未判 SAME（relation miss） |
| 用户真实同事件 | 2/2 | 正常 ALLOW |
| 不同故事 | 2/2 | 正常 REJECT/不合并 |

结论：

- Guard 能阻止故事误归因为用户真实事件；
- 但**同一故事的不同片段目前没有被正确关联**；
- 加入候选 provenance 后，source story_id 已能正确填成 `story-1`/`story-2`；
- 但模型仍不返回 `SAME_EVENT`（一个 None、一个 RELATED_CONTEXT），所以 **story_id 正确并不等于关系判别正确**；
- 连续性需要独立的 story-level 关联策略，不能只靠普通关系标签；
- 因此 R11 仍不能关闭：安全性提高，但记忆连续性未通过。


## 4.3 Gold v2 复核（R11-7A）

原 6 条 continuity 把 `same_story` 与 `same_event` 混在一起，导致 POS-S2 被错误期望为 SAME。修正后：

| 指标 | 结果 |
|---|---:|
| Story membership | **4/4**（2 条 UNKNOWN 未计分） |
| Event relation | **5/6** |
| Real-event contamination | **0** |
| 原判 SAME / RELATED / DIFFERENT / None | 2 / 1 / 2 / 1 |

关键修正：

- POS-S2（同故事、不同情节）的正确答案是 `RELATED_CONTEXT`，不是 SAME；原 0/2 是 Gold 口径错误；
- POS-S1（同故事、同事件补充细节）仍未被判成 SAME，是唯一事件关系 miss；
- story_id 4/4 正确，说明 provenance 可用，但事件同一性仍需独立处理。

因此 R11 仍未关闭，但不是“同故事 0/2”；当前剩余问题是 **同故事同事件的补充细节未合并**。

## 4.4 POS-S1 归因（R11-7B 前置）

POS-S1 的原始失败不是事件同一性判断错误，而是**候选 ID 使用占位符 `candidate`**：

- 模型返回 `candidate_event_id: "evt_1"`；
- Validator 正确判定 `candidate:evt_1` + `missing:candidate`；
- 把候选 ID 换成非占位符 `story-event-1` 后，模型返回正确的 SAME_EVENT。

小规模 ID 对照：

| candidate_event_id | 结果 |
|---|---|
| `candidate` | 模型返回 `evt_1`，被 Validator 拒绝 |
| `evt_1` | SAME_EVENT |
| `S01-E01` | SAME_EVENT |
| `cand_9f3a` | SAME_EVENT |

结论：

- 当前证据支持“测试输入 ID 不真实”而不是 RelationJudge 逻辑缺陷；
- 不需要修改 RelationJudge；
- 不需要引入 StoryAnchor 来修 POS-S1；
- 应先冻结非占位符 ID 的评测夹具，再决定是否需要结构改造。

修正后的 Gold v2：story membership **4/4**、event relation **6/6**、real-event contamination **0**。

## 5. 建议

1. 增加离线 narrative frame 标注：`narrator`, `subject`, `reality_status`, `story_id`；
2. RelationJudge 先判 provenance，再判事件相同；
3. 对第一人称虚构和故事片段做硬失败专项；
4. 不把 R11 合成通过当作真实叙事验收；
5. 在真实脱敏叙事数据到位前，继续保持离线。
