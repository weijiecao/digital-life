# V1.5-B R11-S1/S2：统一 Guard 入口与回放约束

- 报告编号：DL-V1.5-B-REP-021
- 日期：2026-11-08
- 状态：**R11-S1 完成；R11-S2 trace 字段已补，但旧 trace 未重跑**

## 1. R11-S1：Guard 不可绕过

修改 `ConstrainedResolver`：

- 默认构造即持有 `ProvenanceGuard()`；
- 只要 `judgment.provenance != NarrativeProvenance()`，SAME 归属前必须过 Guard；
- 不再依赖调用方显式传入 Guard；
- `RESOLVER` 的旧测试仍使用默认 unknown provenance，因此不改变非叙事行为；
- 新增测试：不传 Guard 的 Resolver 仍会拒绝“虚构→用户真实事件”。

## 2. 移除 fallback attach

`b4_batch_state.py` 原来：

```text
if no resolver attach:
  if trace.final_event exists:
    store.attach_source(..., "state-fallback")
```

这会绕过所有关系/来源判别。

现在：

- **不再按 trace.final_event 直接 attach**；
- 无 attach 时只创建新事件；
- trace final_event 仅用于保持回放事件 ID 可复现，不参与“已有用户事件”的归属。

## 3. Trace 字段

`v1_5b_b4_cluster.py` 新增：

- `source_provenance`
- `candidate_provenance`
- `gate_decision`

这样后续固定 trace 可以复盘 R11 Guard 决策，而不是只存关系标签。

旧 trace 没有这些字段，因此：

- 不重跑旧 trace 的 Guard 断言；
- R11 21 例继续使用独立评测脚本；
- 不能把旧 B4 批次结果当作 Guard 端到端验证。
