### 3.3 P0 缺陷最小复现

```python
st = Store(d, 'fixture-only', FakeEncoder)
st.capture(scope, '1', '备份锁验证', recorded_at='2025-01-01T00:00:00+00:00')
name = st.backup()          # 生成并校验备份
st.close()                  # 关闭主库
Path(d, 'backups', name).unlink()   # → PermissionError: [WinError 32]
```

**根因**（`storage.py:2841`）：

```python
with sqlite3.connect(target) as out:   # 上下文管理器只提交/回滚，不会 close()
    self.flow.db.backup(out)
    ...
# 连接对象 out 在函数返回后仍存活（依赖 GC 回收），文件句柄未释放
```

`recovery.py` 的 `_open_readonly` / `restore_to_new_directory` 都有 `finally: conn.close()`，**仅 `Store.backup()` 遗漏**，是全包唯一的连接泄漏点（已核对全部 4 处 `sqlite3.connect`）。

**影响**（都发生在 Windows / 目标平台）：
1. 备份完成后文件被锁：备份轮转、手工清理、`backups` 目录搬迁会失败；
2. 想用刚生成的备份做"恢复演练"时，可能因占用而失败；
3. 长期运行连续备份会累积句柄；
4. 直接导致本包 **5/225** 测试在 Windows 上失败（另有 3 个因测试自身的同类写法失败，见 P0 建议）。

**建议修复**（一行级别）：

```python
out = sqlite3.connect(target)
try:
    self.flow.db.backup(out)
    if out.execute('PRAGMA integrity_check').fetchone()[0] != 'ok':
        raise ValueError('backup integrity failed')
finally:
    out.close()
```

## 5. 与架构图的关键偏差

1. **① 层无状态标注是正确的**，但容易被读成"没问题"。实际上这是唯一完全没有验证证据的层。
