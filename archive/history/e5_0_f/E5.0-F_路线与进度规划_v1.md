## 0. 本次调整的三个判断

| # | 原计划 | 本次调整 | 理由 |

| 1 | 真实环境联调排在节点 5（后延） | **前移到第 1 个月** | 离线语义的主要不确定性已从"写不出来"变成"不知道准不准"；阈值 0.85/0.75/0.10/0.15 全在模拟编码器上校准，只有真实 BGE 能回答。越晚接，返工面越大 |

## 1. 目标分层与"完成"的定义

### L0 自用版（第 4–6 周）

你自己一台机器、一个私聊号，能连续跑一周不用管。

| 验收线 | 数字 |
|---|---|
| 采集成功率 | ≥ 99%（真实私聊，连续 3 天） |
| 注入生效 | ≥ 95% 的轮次能看到记忆片段 |
| 端到端延迟 | P95 < 1.5 s（不含回复模型） |
| 备份 | 能生成、能校验、能恢复到新目录，且文件可删除 |
| 崩溃/重启 | 重启后积压任务自动续跑，无重复注入 |

### L1 Beta（第 22 周）

能给别人装、能升级、能回退，语义"基本可信"。

| 验收线 | 数字 |
|---|---|
| 目标原话召回率 R@1 | ≥ 70%（评估集，按场景分层） |
| 误注入率 | ≤ 5%（无相关记忆的问题） |
| 纠错场景 | ≥ 60% 同时给出新旧原话并标"未确认" |
| 长历史 | 5,000 条原话下 P95 < 2 s |
| 安装 | 新人照文档 30 分钟内装好 |
| 恢复演练 | 3 次通过（含异常中断） |

### L2 完整目标（开放）

架构图 ⑥ 的三项全部达标 + 部署运维闭环。**这一档没有日历终点**，只有"每季度评估集分数是否还在涨"。

## 3. 阶段详解

### M0 止血（W0，3–5 天）

| 工作项 | 产出 | DoD |
|---|---|---|
| 修 `storage.py:2841` 连接泄漏 | 补丁 + 回归用例 | 备份后 `unlink` 成功；连续备份 10 次无句柄增长 |
| 修测试侧同类写法（`test_store.py:1638/1925/2113`） | 三处改为显式 `close()` | Windows 下 225 用例全绿 |
| 依赖落盘 | `requirements.txt`（版本区间）+ 启动自检 | 缺 `torch`/`sentence-transformers` 时给出单条明确提示 |
| 测试计数自动化 | `scripts/report.py` 输出用例数/通过率/评估分 | 文档不再手写数字（消灭 177/142/225 漂移） |
| **真源清单**：登记桌面 6+ 个 DigitalLife 包，标注权威版本与 E5.0-F 二义性 | `MANIFEST.md`（每包：版本、范围、测试数、是否权威） | 任何人能在 1 分钟内判断"该改哪个包" |
| 收录上游基线实机结果（`E50F` pilot 的运行 JSON/日志） | `docs/baseline_E50F_real.json` + README 标注"实机已验证/未验证" | 基线从"口述"变成"证据" |

### M1 基线对齐与真实闭环（W1–W4）

> 上游 E5.0-F（standalone pilot）是**已实机验证的基线**，下游插件是其延续。M1 先证明"继承成立"，再证明"平台可用"。

| 周 | 工作项 | 风险点 |
|---|---|---|
| W1 前半 | **基线对齐**：用上游 8 条冻结话术 + `e50b` 旧历史夹具直接驱动下游 `Store`（不装 AstrBot），核对 0.55 召回、单会话分段、旧来源早于新消息等边界是否复现 | 上下游评估器不同（`e50b.evaluate` vs `Store`），需先搭桥 |
| W1 | 自建 AstrBot **v4.29.3** + NapCat 测试号 + Python **3.12** + BGE **bge-small-zh-v1.5**（本机未发现 `C:\DigitalLifeTest`，不能假设复用）；插件装载，验证钩子是否被调用、入参字段是否齐全 | AstrBot 版本/钩子签名不匹配 |
| W2 | `message_id` / `message_obj.message` / `unified_msg_origin` 契约核对；采集成功率与缺口记录验证 | NapCat 消息链结构差异 |
| W3 | 注入可见性（`on_llm_request` 是否真被调用、`TextPart` 是否进入上下文）；延迟埋点 | 钩子被调用但片段不生效 |
| W4 | 稳定性：重启续跑、队列积压、单会话 100 条连发；写实机验收报告 | 单线程池被长任务占满 |

**DoD**：连续 3 天真实使用，达到 L0 全部数字；形成《实机验收报告 #1》，含失败样本清单。

### M2 指标与评估集（W5–W8）

1. **先定口径**（W5）：R@1、误注入率、纠错正确率、P95 延迟、自动覆盖率，5 个指标写进文档。
2. **建评估集**（W5–W7）：100 条真实会话样本（脱敏或自造），场景配比建议：
   - 明确事件 20 / 改期改口 20 / 取消否定 15 / 相似事件 15 / 跨日补充 15 / 指代追问 15
3. **跑基线**（W8）：用当前规则版跑分，得到"真实起点"——这是后续所有工作的标尺。

**DoD**：`evaluation/` 下一键复跑，输出每场景分数与失败样本；报告 #1 有数字。

> 这一阶段不写功能代码，只建标尺。**没有这一步，M3 会重演"53 个版本不收敛"。**

### M3 语义校准（W9–W14）

| 工作 | 说明 |
|---|---|
| 阈值重标 | 用真实 BGE 在评估集上网格搜索 0.85 / 0.75 / 0.10 / 0.15，替换模拟编码器时代的经验值 |
| 定点改进 | 只针对 baseline 失败 Top-3 模式（预计是"同义改写""跨事件改期""模糊指代"）动刀 |
| 架构决策点 | 评估"是否把 LLM 判断升为事实变化主路径"：成本、延迟、隐私三项算清再定 |

**DoD**：R@1 提升 ≥15 个百分点，或达到 L1 目标；误注入率不高于基线。若 6 周无显著提升 → 触发 Gate G3 的"换路"决策，而不是继续加规则。

### M4 规模与稳定（W15–W18）

- 语义召回分层（先用倒排/向量粗筛，再精排），替换全量扫描；
- 编码与召回拆出独立线程池，采集链路不被 BGE 阻塞；
- 长事件/多事件：要么放宽上限，要么**明确写成产品约束**（建议后者，个人场景够用）；
- 5,000 条历史压测，出 P95/内存曲线。

**DoD**：压测报告 + 目标机器上的资源占用上限。

### M5 交付硬化（W19–W22）

- 安装/升级/回退文档与脚本；配置 29 个开关收敛成 3 个预设档（关闭 / 自用 / 调试）；
- 备份恢复演练 3 次（含进程中断、文件占用、跨目录恢复）；
- 死代码清理（`engine/e50b`、`e50g`、`e421`，约 570 行）；
- 数据迁移说明（旧库 → 新库，只增不删）。

**DoD**：新人 30 分钟装好；恢复演练全过；L1 六条验收线逐条打勾。

## 4. 指标口径（写进代码，不写进 PPT）

| 指标 | 定义 | 采集方式 | L0 | L1 |
|---|---|---|---|---|
| R@1 | 应召回问题中，返回集合含标注目标原话的比例 | 评估集脚本 | — | ≥70% |
| 误注入率 | 无相关记忆的问题中，注入了任意内容的比例 | 评估集脚本 | — | ≤5% |
| 纠错正确率 | 明确改期/取消场景中，同时给新旧且标未确认的比例 | 评估集脚本 | — | ≥60% |
| P95 延迟 | 钩子进入到注入完成 | 埋点日志 | <1.5 s | <2 s |
| 自动覆盖率 | 无需人工命令即产生召回的轮次占比 | 实机统计 | ≥80% | ≥90% |

## 7. 节奏与跟踪方式

- **周节奏**：周一 30 分钟定本周 1 个主目标；周五跑全量回归 + 更新指标看板；不追进度百分比，只看指标曲线。
- **版本号**：M1 出 `v0.16.0`（实机闭环），M3 出 `v0.17.0`（语义校准），L1 出 `v1.0.0`。停止 `0.15.x` 递增——那套编号已经不承载信息。
- **单一事实源**：用例数、通过率、五项指标全部由脚本生成到 `STATUS.md`，文档只引用不手抄。
- **看板四泳道**：语义 / 工程 / 验收 / 交付，每张卡必须带"可复跑的证据"才算完成。

## 8. 明确不做（Non-goals，本版）

1. 不做群聊、多人、多设备同步；
2. 不做自动事实确认（一切结论保持"未确认"）；
3. 不为 5,000 条以上做专项优化，除非压测证明个人场景会触达；
4. 不做"通用语义理解"，只做"可验证的召回 + 不确定标注"；
5. 不让用户参与日常审核（人工命令仅保留为诊断/兜底）。
