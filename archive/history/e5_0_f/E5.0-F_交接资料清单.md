# E5.0-F 交接资料清单

> 用途：接手方（或未来的你）按此清单准备材料。代码本身不是瓶颈——本包已自带 6,500 行运行时与 225 个用例。
> 真正决定接手速度的是三类"代码之外"的东西：**真实环境事实、目标与验收意图、决策历史**。

---

## A. 必须（缺一项就无法真正接手）

| # | 资料 | 为什么必须 | 缺失后果 |
|---|---|---|---|
| A1 | **完整仓库 + Git 历史**（不只 zip） | 53 个版本只留了 changelog，看不到被回滚的尝试、提交粒度与提交信息 | 会重复走已失败的路；无法判断哪段代码是"临时补丁" |
| A2 | **可运行的真实实例**：AstrBot 版本号、NapCat 版本、插件装载成功日志 | 架构图①层至今零验收，钩子契约是本项目最大未知 | M1 无法开始，只能继续在模拟环境里打转 |
| A3 | **一条真实私聊消息的结构样例**：`message_obj`、`message` 链、`unified_msg_origin` 实际值 | 测试里用 `test:FriendMessage:42`，真实值格式未知；采集依赖 `message_id` 与纯文本链严格匹配 | 采集可能全量失败而无人察觉（失败是静默的） |
| A4 | **BGE 模型信息**：具体型号、来源、目录、维度、单条编码耗时 | 所有语义阈值（0.85/0.75/0.10/0.15）都是模拟编码器时代的经验值 | 语义召回可能整体失准，且无法判断是 bug 还是阈值问题 |
| A5 | **200–500 条脱敏真实语料 + 场景标注** | 现有 15 项是固定夹具，无法回答"真实对话召回率多少" | 无法建立 R@1/误注入率基线，M3 没有标尺 |
| A6 | **"完成"的验收口径**：谁验收、什么算通过、优先级 | ⑥ 三项只写"待完成"，没有数字 | 无法判断距离，也无法决定何时停手（53 版不收敛的根因） |
| A7 | **隐私与成本红线**：哪些内容绝不外发、是否允许远程模型、月预算、可接受延迟 | 当前"默认不调用远程模型"是隐含约束，但语义上限受它限制 | 可能在错误的架构约束下做几个月优化 |

## D. 建议的交接形式

1. **一份 `HANDOVER.md`**：环境、账号、目录、启动方式、常见故障、当前已知缺陷（含本次发现的备份句柄问题）。
2. **一次 90 分钟口述录音**：讲决策史——为什么默认全关、为什么不用现成向量库、为什么放弃某条路线、哪些阈值是拍的。这类信息写不进代码，但决定后来者是否走弯路。
3. **三个可复跑样例**：① 真实消息结构 dump；② 真实 BGE 编码输出；③ 一条真实对话的端到端日志（含耗时）。
4. **一个可登录的测试实例**，而不是截图。

## F. 如果只能给三样

1. **带 Git 历史的仓库**；
2. **一个能登录的真实 AstrBot + NapCat 实例**（附一条消息结构 dump）；
